## 二、关键发现与技术情报

### 2.1 微信 4.x 保护体系(完整测绘)

```
┌─ 保护层 1: 文件完整性自检 ─────────────────────────────────┐
│  启动时校验 DLL 版本一致性 + 文件哈希                      │
│  实测: 破解了(等长版本替换 + 跳过校验分支)               │
├─ 保护层 2: RTTI 类名清零 ─────────────────────────────────┤
│  TypeDescriptor.name 全部置零, 无法通过 RTTI 识别类       │
│  实测: 确认(读取为全零)                                  │
├─ 保护层 3: R3 内存 CRC ──────────────────────────────────┤
│  按需触发, 消息操作时校验 .text 代码完整性                │
│  实测: INT3 → 立即崩溃(反篡改响应)                      │
├─ 保护层 4: UIA 关闭 ─────────────────────────────────────┤
│  Qt 5.15.14 窗口仅暴露 1 个元素(窗口本身)                │
│  实测: 确认(整个窗口树只有根节点)                       │
├─ 保护层 5: 字符串全量加密 ────────────────────────────────┤
│  内存中所有字符串(UI 输入/RTTI/日志标签)加密存储          │
│  实测: 输入框文本/联系人/消息缓存均搜不到明文             │
├─ 保护层 6: 间接派发 ─────────────────────────────────────┤
│  函数通过 std::function/vtable 间接调用, 无直接调用链     │
│  实测: E8 搜索 0 命中, vtable 搜索 0 命中                │
├─ 保护层 7: 服务端版本门槛 ───────────────────────────────┤
│  按账号状态拒绝低版本客户端(不信任客户端声明)             │
│  实测: 3.9.11.17 / 3.9.12.17 / 4.9.9.99 全部被拒         │
└───────────────────────────────────────────────────────────┘
```

### 2.2 核心技术发现

**版本号整型编码:**
```c
uint32_t version = ((0x60 + major) << 24) | (minor << 16) | (patch << 8) | build;
// 例: 3.9.5.81 → 0x63090551
// 例: 4.1.13.65 → 0x64010D41
```

**发送管线调用链**(Frida 网络层回溯实测):
```
send() [ws2_32.dll]
  ← 0x4D34740 (网络层, 443B)
    ← 0x4DED3B0 (序列化/加密, 3KB)
      ← 0x732E220 (消息分发, 666B)
        ← 0x731D6EC (路由, 94B)
          ← 0x71659EC (路由, 60B)
            ← 0x6A1A0 (1.7KB, 字符串编码工具)
              ← ... (更上层, 未完全追踪)
```

**消息管理器日志串(函数名线索):**
```
CoAddGroupMessageListToDb / CoAddMessageListToDB
SaveSendMessagesAtOnce / GetAddSendMessageToDb
CoPrepareShowMessage / Begin StartSendMessageSyncStage
SendMsgFailed / CheckMessageLiveStatus / BuildCompleteMessageWrapper
```

### 2.3 被否定的路线(避免重复踩坑)

| 尝试 | 结果 | 教训 |
|---|---|---|
| 3.9.5.81 内存版本伪装(4.x 编码) | ❌ 服务端拒绝 | 上报版本不在客户端可修改范围 |
| 3.9.5.80 文件版本改为 4.9.9.99 | ❌ 微信自检崩溃 | 文件完整性校验(两层) |

## 五、关键教训(TL;DR)

1. **服务端版本门槛无法用客户端技术绕过** —— 改内存/改文件/改注册表都无效,判定在服务器
2. **微信 4.x 保护是全方位的** —— 字符串加密 + RTTI 清零 + CRC + UIA 关闭 + 反调试
3. **内容锚点搜索不可行** —— 所有字符串加密,无法通过搜内容定位代码
4. **间接派发阻断静态分析** —— 无直接调用链,必须用 Ghidra/Frida 动态追踪
5. **网络层回溯是有效的** —— `ws2_32!send` 的 backtrace 给出了真实调用链
6. **硬件断点是最安全的观测手段** —— 零字节修改,CRC 不可见
7. **商业框架存在的意义** —— 持续对抗需要专职团队,个人逆向难以为继
